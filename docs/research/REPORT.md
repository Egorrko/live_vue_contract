# Контракт props LiveView ↔ Vue: отчёт

Стенд A — закрытый продукт на Phoenix + Ash + LiveVue; имена модулей и полей в отчёте заменены
на нейтральные, числа настоящие. Базовая линия 2026-09-14:
`mix compile --warnings-as-errors` зелёный, `mix test` 354/354, `vue-tsc` 18 ошибок
(3 в `deps/live_vue/assets/server.ts`, 8 `TaskForm.vue`, 5 `ItemForm.vue`,
2 `ReportForm.vue`; `mix compile`/`mix test` их не видят — типы на стенде ничего не охраняют).

## 4. Прототип: `livevue_contract` (направление B + compile-time проверка тега)

Библиотека росла в рабочей папке исследования (`mix.exs`, `lib/`, `priv/gen.mjs`, 4 своих теста), с 2026-09-19
живёт в этом репозитории (см. раздел 6). В стенд подключена на отдельной ветке.

**Источник правды — `defineProps<T>()`.** Ничего нового руками не описывается ни на одной стороне.

```
.vue (defineProps<T>)  --vue-component-meta-->  assets/vue/contract.json  (Mix-компилятор, по mtime)
                                                       │
                     ┌─────────────────────────────────┴──────────────────────────────┐
     ~H на компиляции: атрибуты <.vue v-component="X"> ⟷ ключи схемы X        vue/1 на рендере (dev/test):
     missing required / не объявлен / нет такого компонента → CompileError     Encoder.encode(props) ⟷ вложенная схема
                                                                               → ArgumentError с путём (/items/0/statusLabel)
```

Четыре части, ~250 строк:

| Часть | Что делает | Где |
|---|---|---|
| `priv/gen.mjs` | `vue-component-meta` (Volar, тот же движок, что у `vue-tsc`) читает `props[].schema` каждого `.vue` и пишет JSON-Schema-подмножество: `object/array/string/number/boolean/null/enum/anyOf/any`. Библиотечные и generic-типы (`Form<…>`, `Record<…>`) → `any` | 90 строк JS |
| `Mix.Tasks.Compile.LiveVueContract` | `compilers: [:live_vue_contract, …]`; если любой `.vue` новее `contract.json` — `node gen.mjs`. ~3 с на регенерацию, 0 если ничего не менялось | 35 строк |
| `LiveVueContract.sigil_H` | оборачивает `LiveVue.SharedPropsView.sigil_H` (он уже переопределяет `~H` ради shared props), а затем обходит **скомпилированный AST HEEx**: ищет `component(&vue/1, %{…})` и шорткаты `component(&ItemList/1, …)`, берёт ключи мапы и литерал `v-component`. Никакого своего парсера шаблонов. Ставит `@external_resource contract.json`, так что смена `.vue` перекомпилирует LiveView | 60 строк |
| `LiveVueContract.vue/1` + `Schema.validate/2` | замещает импорт `LiveVue.vue/1`; в dev/test валидирует закодированные props по вложенной схеме и бросает `ArgumentError`; в prod выключается конфигом. Лишний ключ *внутри* значения — предупреждение (TS структурный, клиент его просто не читает), `strict: true` делает ошибкой | 110 строк |

Подключение в стенд — 4 строки: dep, компилятор, `use LiveVueContract` вместо импорта
`SharedPropsView`, `validate: false` в prod. 19 вызовов `<.vue>` не тронуты. `defineProps<T>` остаётся у фронтендера.

## 5. Честный абзац: что прототип не ловит и сколько стоит закрыть

- **Ловит только то, что рендерится.** Режимы 1, 4, 5 — на `mix test`, но лишь для экранов, которые какой-нибудь
  live-тест монтирует (на стенде 15 из 19 корней). Новый экран без теста получает
  только compile-проверку ключей и dev-рантайм. Закрыть до конца — генерировать смоук-тест «смонтировать каждый LiveView»
  нельзя универсально (auth, фикстуры); честный остаток — правило «у каждого корня есть live-тест».
- **`any` для generic/библиотечных типов.** `form: Form<T>` и любой `Record<…>` не проверяются вовсе.
  Стоимость: раскрыть `Form<T>` через `schema.ignore`/специальный маппинг в `gen.mjs` (~20 строк) — но тип формы
  LiveVue сам по себе слабый, выигрыш небольшой.
- **Лишние вложенные ключи — предупреждение**, не ошибка (иначе стенд с 10 реальными расхождениями сразу красный).
  `config :livevue_contract, strict: true` — одна строка, когда корпус вычищен.
- **Динамика пропускается молча.** `v-component={@name}` и `<.vue {@rest}>` compile-проверку не проходят
  (проверяется только литерал и явные атрибуты). Стоимость: предупреждение компилятора, 5 строк.
- **Шорткаты `<.ItemList>`** проверяются на компиляции, но не в рантайме: `LiveVue.Components` зовёт
  `LiveVue.vue/1` напрямую, минуя замещённый импорт. Закрыть — правка в 1 строку внутри LiveVue
  (`name_to_function` должен звать `vue/1` вызывающего модуля) — кандидат в PR, на стенде не нужен: шорткаты не используются.
- **Типы плоские по JSON.** `Date` и `DateTime` оба `string`, `integer` и `float` оба `number`; смена `:date` на
  `:utc_datetime` в ресурсе невидима. Закрыть можно только соглашением о branded-типах (`type ISODate = string`) плюс
  `format` в схеме — третье описание в миниатюре, не делал.
- **Свежесть `contract.json` в CI без node.** Компилятор регенерирует по mtime; после `git checkout` mtime случайны,
  и без `node` компилятор упадёт. Нужен `mix live_vue_contract.check` (регенерация + `git diff --exit-code`)
  или сборка `contract.json` в том же шаге, что и vite. ~20 строк, не сделано.
- **События (режим 7) не тронуты.** Дорога открыта: `vue-component-meta` отдаёт и `events`, `pushEvent`/`useLiveEvent`
  можно обернуть типизированными хелперами и читать тем же генератором; на стороне Elixir у `handle_event` объявления
  нет — потребуется либо `@spec`-подобная аннотация, либо проверка по факту в тестах (`render_hook`). Порядок — дни, а не часы.
- **Ash ни при чём, LiveVue не форкнут.** Поломка 3a показала, что смена типа в ресурсе ловится Ash-кастом раньше
  провода; контракт нужен ровно для 3b — когда домен доволен, а провод изменился.

## 6. Второй стенд: `freakland` (2026-09-19) — библиотека как зависимость

Задача владельца: «добавил библиотеку — и заработало». Библиотека переупакована (`:live_vue_contract`):
`use LiveVueContract` заменяет и `use LiveVue`, и `use LiveVue.Components` (шорткаты берутся из
`contract.json`, `vue_root` не дублируется), `~H` по умолчанию оборачивает штатный `Phoenix.Component`
(`shared_props: true` — через `LiveVue.SharedPropsView`, как на первом стенде), свежесть контракта
считается по хэшу `assets/**/*.{vue,ts}`, записанному в сам файл, — закоммиченный `contract.json`
компилируется без `node` (в Dockerfile freakland `mix compile` идёт до `COPY assets`: без `.vue` компилятор
просто молчит). Подключение в реальный проект — 3 строки в `mix.exs`, 1 в `freakland2_web.ex`,
`npm i -D vue-component-meta` той же версии, что `vue-tsc`.

Что сломалось при переносе и починено:

| Симптом | Причина | Правка |
|---|---|---|
| валидация молчала на всех тестах | Mix компилирует зависимости в `MIX_ENV=prod`, `Mix.env() != :prod` внутри библиотеки всегда `false` | решение в рантайме: есть `Mix` и он не `:prod` → валидировать; релиз — нет |
| `contract.json` 20 МБ | проп `anchor: HTMLElement` раскрыл весь DOM | `schema.ignore`: типы, объявленные только в `lib.*.d.ts` TypeScript и без параметров, не раскрываются → `any` |
| 63 ложных `expected one of [...], got :text` | атомы `:text` в enum сравнивались со строками | атом → строка перед сравнением, как на проводе |
| `expected null \| object, got %{...}` | из `anyOf` выбиралась ветка с меньшим числом ошибок, а не структурно подходящая | ранжирование: сначала «совпал ли тип», потом число ошибок; вложенные ошибки видны по пути |
| `/players: missing required key` | `players={@streams.players}` — LiveStream | ключи-стримы исключаются из `required`, не валидируются |
| новый проект с дрейфом краснеет целиком | ошибки контракта — исключения | `config :live_vue_contract, validate: :warn` — только лог |

Базовая линия freakland: `mix compile` зелёный, `mix test` 639/657 (18 красных — S3 и обработка тайлов,
окружение), `vue-tsc` 0. С библиотекой: `mix compile` зелёный, все 19 литеральных `<.vue>` прошли
проверку атрибутов; `mix test` **636/657** — 3 новых красных из-за одного настоящего расхождения:
`MentionedPlayer.share_path` объявлен в `assets/vue/shitpost.ts`, а `ShitpostLive.active_players_snapshot/0`
и проекция `mentioned_players` его не отдают (`ShitpostPage`, `PlayerPage`). Плюс 28 предупреждений
«сервер шлёт ключ, которого нет в типе» (`hidden_at`, `moderation_note`, `started_at`, `reaction_score`…).

Поломки критерия на freakland:

| Поломка | Результат |
|---|---|
| 1 `server.online_count` → `onlineCount` во всех трёх строителях | `mix test`: `/server/online_count: missing required key`, +~80 красных (все экраны с `HomePage`) |
| 2 `total: number` в `defineProps` HomePage, `<.vue>` не передаёт | `mix compile`: `home_live.ex:60: missing required prop "total"` |
| 3 `online_count` уходит строкой | `mix test`: `expected number, got "0"` |

Не ловится по-прежнему: динамический `v-component={component(assigns, "PlayersPage")}` — только в рантайме;
